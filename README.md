# OfficeAIPj01

オフライン・CPU 環境向けの、ローカル LLM 活用プロジェクト。

開発の経緯・設計判断・未着手のテーマは [HANDOVER.md](HANDOVER.md) にまとめています。

## chat_app.py — ローカルLLM チャットアプリ (Tkinter)

Python 標準ライブラリ (Tkinter) だけで動く、エージェント的に拡張可能なチャット UI。
`llama-cpp-python` 経由で GGUF モデルを CPU 推論し、生成結果をストリーミング表示します。

既定値は **Gemma 4** (E2B / E4B / 12B ほか) を前提に合わせています。

### 特徴
- 追加インストール不要 (Tkinter は Python 標準。要 `python3-tk` パッケージ)
- モデル選択 / temperature / top_p / top_k / max_tokens を UI から調整
- 生成トークンのストリーミング表示、生成の停止、直前の応答の再生成
- システムプロンプトと思考 (reasoning) モード。思考は折りたたみ表示
- ファイル添付 (画像 / PDF / Word / Excel / テキスト系。PDF はページ画像としても渡せる)
- カメラからの取り込み (プレビューを見ながら撮影して、そのまま添付)
- 回答をファイルに保存 (回答全体を `.md` / Word、表を Excel、コードブロック単体を `.csv` / `.py` などで)
- 出力形式「Excel 表」「Word 文書」: 回答を表・文書の形で作らせ、そのまま `.xlsx` / `.docx` に保存
- ターミナルに動作状況 (状態遷移・初トークン遅延・tok/s 等) を随時デバッグ出力
- `llama-cpp-python` 未導入時やモデル未検出時は「モックモード」で UI 確認が可能

### 画面の構成
| 場所 | 内容 |
| --- | --- |
| 左サイドバー | 新規チャット / タイトルでの絞り込み / 会話一覧（クリックで開く、Ctrl・Shift + クリックで複数選んで削除、右クリックメニュー） |
| ヘッダー | モデル選択・読み込み・フォルダ選択。右端の **「設定」** で詳細設定パネルを開閉 |
| 詳細設定パネル | システムプロンプト、temperature / top_p / top_k / max_tokens（「既定値に戻す」あり）、PDF を画像として読む |
| チャット欄 | 発話ごとに見出しと余白を付けて表示。右クリックでコピー / すべて選択 / 最後の回答をコピー |
| 入力欄 | ファイル添付・カメラ・**出力形式**（チャット / Excel 表 / Word 文書）・思考モード・回答の保存・再生成。添付があるときだけ添付一覧が出る。送信ボタンは生成中「停止」に変わる |
| ステータスバー | モデルの状態（未読み込み / 読み込み済み / モック / 失敗）、処理状況と進行表示、コンテキスト使用量 |

詳細設定パネルの開閉と文字の大きさは `chat_settings.json` に保存され、次回も同じ状態で開きます。

### 実行
```bash
python chat_app.py

# モデル (.gguf) の置き場所を指定する場合
LLM_MODELS_DIR=/path/to/models python chat_app.py
```

### 環境変数
| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| `LLM_MODELS_DIR` | 設定ファイル → カレント | `.gguf` を探すフォルダ。指定すると設定ファイルより優先 |
| `LLM_MMPROJ` | 自動検出 | 画像入力に使う mmproj ファイルの明示指定 |
| `LLM_N_CTX` | `16384` | コンテキスト長。長いほどメモリを消費する |
| `LLM_MAX_TOKENS` | `2048` | 1 回の応答の最大トークン数 (UI からも変更可) |
| `LLM_THINKING_TOKENS` | `2048` | 思考モードのときに `max_tokens` へ上乗せする枠 |
| `LLM_N_THREADS` | 物理コア数 | 文字を生成するときのスレッド数 |
| `LLM_N_THREADS_BATCH` | 論理コア数 | 入力を読み込むときのスレッド数 |
| `LLM_FLASH_ATTN` | `1` | Flash Attention を使う。`0` で無効 |
| `LLM_KV_TYPE` | `q8_0` | KV キャッシュの型（`q8_0` / `f16` / `q4_0`）。Flash Attention が有効なときだけ効く |
| `LLM_STDIO_ENCODING` | `utf-8` | ログ出力の文字コード。`none` で変更しない |
| `LLM_CAMERA_INDEX` | `0` | 使うカメラの番号。外付けを使うなら `1` 以降 |

### 回答をファイルに保存する
入力欄の上の **「回答を保存...」**（または `Ctrl+S`）で、直近の回答をファイルにできます。
保存する内容は次の中から選びます。

| 候補 | 内容 |
| --- | --- |
| 回答全体 (.md) | 回答をそのまま Markdown で |
| 回答全体 → Word (.docx) | 見出し・段落・箇条書き・番号付き・表・コードを Word の書式にして |
| 表 n → Excel (.xlsx) | 回答中の Markdown の表、または `` ```csv `` / `` ```tsv `` のブロックを Excel に。表が複数あれば「すべての表」(1 表 1 シート) も選べる |
| コードブロック n | ブロック単体。拡張子は言語名から（`csv` → `.csv`、`python` → `.py`、不明なら `.txt`） |

- 最初に選ばれているのは、Markdown の表があれば Excel、コードブロックがあればそのブロック、どちらも無ければ回答全体です
- 保存先は毎回ダイアログで選びます（前回のフォルダを覚えています）。モデルが勝手に書き込むことはありません
- CSV / TSV は **BOM 付き UTF-8** で保存します。日本語版 Excel でそのまま開いても文字化けしません
- 途中で切れた（閉じていない）コードブロックは候補に出しません

ファイルにしたい内容があるときは、たとえば次のように頼むと確実です。

```
来月の当番表を作って。ファイルにしたいので CSV のコードブロックで出力して
```

毎回書くのが面倒なら、詳細設定のシステムプロンプトに
「ファイルにする内容はコードブロックで出力すること」と入れておく方法もあります。

### Excel / Word で出力する
入力欄の上の **「出力」** を「Excel 表」または「Word 文書」にしてから送信すると、
回答を表・文書の形で作らせ、終わったところで保存先を聞きます（チャットメニューからも切り替え可）。

```
出力: Excel 表   →  「来月の当番表を作って。月〜金、田中・佐藤・鈴木で回す」
出力: Word 文書  →  「この議事メモを報告書の形にまとめて」(メモを貼り付けるか添付)
```

- モデルの出力を **JSON スキーマで縛ります**（llama-cpp-python の `response_format`）。
  形の崩れた出力は文法上出せないため、小さなモデルでも確実に表・文書の形になります
- 生成中は JSON がそのまま流れ、終わると読める表・文書の表示に置き換わります。
  会話履歴にも読める形で残るので、続けて「列を増やして」などと頼めます
- Excel では、見出し行が太字で固定され、列幅は内容に合わせます。数値に見えるセルは数値になります
  （`1,200` → 1200）が、`007` のように先頭が 0 のものは文字のまま残します
- **思考モードは使いません**（JSON の文法で縛るため、思考の記号を出力できなくなります）
- 表が長いと `max_tokens` に達して途中で切れ、ファイルを作れません。そのときは詳細設定で増やしてください
- Excel の書き出しは標準ライブラリだけで行うので **openpyxl は不要**です。Word には `python-docx` が要ります

### 速度について（CPU 推論）
アプリ側で次の対策を自動で行っています。

- **画像を含まないターンは、前回までの計算結果を再利用します。**
  画像用の経路（mmproj 使用時）は毎回会話全体を読み直すため、会話が長くなるほど返事が遅くなっていました。
  画像を含まないターンだけ通常の経路に切り替え、新しく増えた部分だけを読むようにしています
  （プロンプトの書式は同じテンプレートなので変わりません）
- **Flash Attention と KV キャッシュの量子化（q8_0）** で、長い入力の読み込みとメモリの読み書きを軽くします。
  使えない環境では自動で外して読み込みます
- **スレッド数**は、生成を物理コア数、入力の読み込みを論理コア数にしています
- ステータスバーに「応答開始まで N 秒」（入力の読み込みにかかった時間）と生成速度（tok/s）を出すので、
  効果はそこで確認できます

使い方の面でできること（効果の大きい順）:

1. **電源につなぎ、Windows の電源モードを「最適なパフォーマンス」にする**。
   省電力の CPU（15W）はバッテリー駆動や「バランス」で大きく速度が落ちます
2. **思考モードは必要なときだけ**。思考の分だけ数百トークン余計に生成します
3. **添付は必要な部分だけ、長くなった会話は「新規チャット」で**。読み込む量がそのまま待ち時間になります
4. **軽い用途は E2B を使う**。E4B より小さいぶん速く動きます（そのぶん賢さは下がります）
5. ブラウザなど重いアプリを閉じる（メモリの帯域を取り合うため）

### ログが文字化けするとき
日本語の Windows では、Python の出力 (既定は cp932) とターミナルの解釈が食い違ってログが化けます。
**片側だけ UTF-8 にしても直らない**ため、起動時に次の両方を行って揃えています。

1. コンソールのコードページを UTF-8 (65001) に変更
2. stdout / stderr も UTF-8 で書き出す

起動直後に、実際に何をしたかを ASCII のみのログで出します (化けていても読めます)。

```
console codepage: out 932->65001, in 932->65001
stdout: cp932 -> utf-8
state: encoding=utf-8 isatty=True platform=win32
```

それでも化ける場合は、この 3 行の内容が切り分けの手がかりになります。
cp932 のまま使いたい場合は次のように指定してください。

```powershell
$env:LLM_STDIO_ENCODING="cp932"; python chat_app.py
```

### モデルの置き場所
モデル一覧の右にある **「フォルダ...」** でフォルダを選ぶと、その場で一覧が入れ替わり、
**選んだ場所は `chat_settings.json` に保存されます**。次回起動時に自動で読み込まれるので、
毎回指定し直す必要はありません。

参照場所は次の順で決まります。

1. 環境変数 `LLM_MODELS_DIR`（指定されていれば最優先）
2. `chat_settings.json` の `models_dir`（「フォルダ...」で保存される値）
3. カレントディレクトリ

`LLM_MODELS_DIR` を設定したまま「フォルダ...」で変更した場合、その回は切り替わりますが、
次回起動時は環境変数の方が使われます（その旨をチャット欄に表示します）。
恒久的に設定ファイルで管理したい場合は、環境変数を外してください。

`chat_settings.json` を直接編集しても構いません。

```json
{
  "models_dir": "D:\\Users\\xxx\\Desktop\\gguf",
  "system_prompt": "",
  "temperature": 1.0
}
```

### Gemma 4 向けの既定値
サンプリングの初期値は Google 公表の推奨値に合わせています。UI から変更できます。

| 項目 | 既定値 | 備考 |
| --- | --- | --- |
| `temperature` | `1.0` | Google 推奨値 |
| `top_p` | `0.95` | Google 推奨値 |
| `top_k` | `64` | Google 推奨値 |
| `max_tokens` | `2048` | 1 回の応答の上限。思考モード時は自動で +2048 |
| `n_ctx` | `16384` | 会話全体の長さの上限 |

用途に応じて `temperature` を下げると安定します (コーディング・事実確認なら 0.1〜0.3、
通常の会話で 0.6〜0.8、創作寄りで 0.8〜1.0 が目安)。

### 回答が途中で切れるとき
原因は 2 つあり、どちらもステータス表示で見分けられます。

1. **`max_tokens` 到達** — ステータスが「打ち切り」になり、
   `max_tokens に達したため回答が途中で終わりました` と表示されます。
   `max_tokens` を増やして「再生成」してください
2. **コンテキスト不足** — ステータスの `コンテキスト 15200/16384 (92%)` が上限に近い状態です。
   85% を超えると警告を出します。新しいチャットを始めるか `LLM_N_CTX` を増やしてください

思考モードでは思考トークンも同じ予算を消費するため、有効にすると `max_tokens` に
自動で `LLM_THINKING_TOKENS` (既定 2048) を上乗せします。

**停止語** は、モデル名に `gemma-4` が含まれる場合は特殊トークン (`<turn|>` `<|turn>` 等) だけを使います。
チャットテンプレートが効くため「あなた:」のような自然文の停止語は不要で、
むしろ応答にその語が含まれると途中で切れてしまうためです。それ以外のモデルでは従来どおり付けます。

### 思考 (reasoning) モード
Gemma 4 はシステムプロンプトの先頭に `<|think|>` を置くと、回答の前に思考を出力します。
「思考モード」にチェックを入れると自動で付きます (システムプロンプト欄に自分で書く必要はありません)。

思考は `<|channel>thought … <channel|>` という区切りで届くので、これを解析して
`[思考]` の見出しを付けた**紫色の小さな文字で表示**し、最終回答と混ざらないようにしています。
思考と回答の間には改行を入れます。「思考を表示」のチェックを外すと、見出しと区切りごと
折りたたまれ、回答だけが残ります。

思考は**履歴に保存せず、次のターンのモデル入力にも渡しません**。

### 会話が伸びてもシステムプロンプトを効かせる
毎回の送信では、システムプロンプトを先頭に置いたうえで会話履歴を丸ごと渡します。
そのため会話が伸びるとコンテキストを圧迫し、放っておくと llama.cpp が
`Requested tokens exceed context window` で落ちます。

これを避けるため、送信前に **`n_ctx` − 生成枠 − 余白** を予算として、次の順で調整します。

1. 予算に収まっていれば何もしない
2. 収まらなければ、**最新の 1 件を除いて画像を外す**
   (画像は 1 枚で数百トークン使うわりに、後続のターンで参照されないことが多い)
3. それでも収まらなければ、**古い発話から落とす**

**システムプロンプトと最新の発話は必ず残す**ので、会話が長くなっても
システムプロンプトが押し出されることはありません。

削るのは**そのときモデルへ送る内容だけ**で、画面の表示と保存済みの履歴はそのまま残ります。
調整が入った回は `コンテキストに収めるため、古い発話 4 件を今回の送信から外しました` と表示します。

### システムプロンプトと設定の保存
システムプロンプトは 2 か所に保存されます。

| 保存先 | 内容 | 読み込まれるタイミング |
| --- | --- | --- |
| `chat_sessions/<会話ID>.json` | その会話で使っていたシステムプロンプトと思考モード | サイドバーからその会話を開いたとき |
| `chat_settings.json` | 次に新しいチャットを始めるときの初期値 | アプリ起動時 |

`chat_settings.json` にはシステムプロンプトのほか、**モデルフォルダ**・思考モード・
思考の表示・サンプリング値・`max_tokens`・PDF の扱い・最後に使ったモデルを保存します。
アプリを閉じたときに書き出し、次の起動時に復元します
(前回のモデルが見つからない場合はモデルだけ復元しません)。
モデルフォルダだけは「フォルダ...」で選んだ時点で即座に保存します。

どちらもローカルのファイルで、`.gitignore` 済みです。

### ファイル添付
入力欄の上にある「ファイル添付」から、次の送信に添付するファイルを選びます。

**文書ファイル** はテキストへ変換して本文に埋め込むため、モデル側の対応は不要です。

| 形式 | 必要なライブラリ |
| --- | --- |
| `.txt` `.md` `.csv` `.json` `.py` などテキスト系 | 不要 (UTF-8 → CP932 の順で試行) |
| `.pdf` | `pypdf` |
| `.docx` | `python-docx` |
| `.xlsx` `.xlsm` | `openpyxl` |

ライブラリが入っていない形式を選んだ場合は、必要な `pip install` を案内するだけで
アプリは落ちません。1 ファイルあたりの取り込みは 6000 文字で打ち切ります。

添付した画像は、チャット欄に**幅 200px のサムネイルで表示**されます。何を渡したのかが
後から見て分かるようにするためで、モデルへ渡すのは縮小前の元画像です。
サムネイルの生成には Pillow を使い、無ければ OpenCV を使います。どちらも無い場合は
サムネイルを出さないだけで、添付そのものは通常どおり動きます。

モデルへ渡す本文には**画像のファイル名を書きません**。「画像について書かれた文」と
「画像そのもの」の両方が入っていると、画像が 2 枚あると解釈されてしまうためです。
ファイル名は画像パートに持たせておき、保存やタイトル生成のときだけ
`[添付画像: 名前]` の形で書き出します。

なお会話履歴の JSON には画像を保存しないため、**過去の会話を開き直したときは
サムネイルも出ません**（`[添付画像: 名前]` の記述だけが残ります）。

#### カメラから取り込む
「カメラ」ボタンで小窓が開き、プレビューを見ながら「撮影」を押すと、その 1 コマが
`camera_20260804_153012.png` のような名前で**そのまま添付に入ります**。ファイルには保存しません。
撮影後も小窓は開いたままなので、続けて何枚でも撮れます。

- **`opencv-python` が必要**です (導入済み。未導入なら `pip install opencv-python`)
- 画像として渡すので **mmproj が必要**です。無い場合は撮影時に警告を出します
- 「左右反転」はプレビューと撮影の両方に効くので、**見えている通りの向きで撮れます**
- 別のカメラを使うときは `LLM_CAMERA_INDEX=1` のように指定してください
- カメラの読み取りは別スレッドで回しているので、プレビュー中も UI は固まりません
- アプリ終了時にカメラは必ず解放します (掴んだままだと他のアプリから使えなくなるため)

#### PDF を画像として読ませる
PDF はまずテキスト抽出を試み、**文字が取れなかった場合 (スキャン PDF など) は
自動でページ画像に変換**してモデルへ渡します。図表やレイアウトごと見せたいときは
「PDFを画像として読む」にチェックを入れると、常にページ画像として渡します。

画像化には `pypdfium2` と `pillow`、そして画像入力なので **mmproj が必要**です。
1 ファイルにつき先頭 4 ページまで、144dpi 相当 (`PDF_IMAGE_MAX_PAGES` /
`PDF_IMAGE_SCALE`) で変換します。

**画像** (`.png` `.jpg` `.webp` など) を渡すには、マルチモーダル対応モデル (Gemma 4 等) と、
対になる **mmproj ファイル** (`mmproj-*.gguf`) の両方が必要です。モデルと同じフォルダに
置くと自動検出します (`LLM_MMPROJ` で明示指定も可)。mmproj が見つからない場合は
画像なしで読み込み、画像を添付して送信しようとした時点でその旨を表示します。
状態は読み込み完了メッセージの「画像入力 可 / 不可」で確認できます。

なお、会話履歴の JSON には画像そのもの (base64) は保存しません。会話を再開すると
`[添付画像: 名前]` という記述だけが残り、画像は再度添付し直す必要があります。

### 生成の制御
- **停止**: 生成中に押すと打ち切ります。そこまでの応答は履歴に残ります
- **再生成**: 直前の応答を捨てて、同じ入力で生成し直します
- 生成が終わるとステータスに `完了 (128 tokens, 4.2 tok/s) / コンテキスト 1520/8192 (18%)`
  のようにトークン数・生成速度・コンテキスト使用量を表示します

コンテキスト使用量が 85% を超えると警告を出します。`LLM_N_CTX` を大きくするか
新しいチャットを始めてください (E2B / E4B の上限は 128K、12B 以上は 256K ですが、
長くするほどメモリを消費します)。

### 必要に応じて
実推論には `llama-cpp-python` と GGUF モデル (`Models.txt` 参照) が必要です。
画像入力には `llama-cpp-python` 0.3.33 以降 (`Gemma4ChatHandler` を含むバージョン) が必要です。
GUI を使うには OS 側に Tk が必要です (例: Debian/Ubuntu なら `apt install python3-tk`)。
